# 发展路线与验收

更新：2026-10-28。目标是个人多客户端的可靠知识中枢，保留 Markdown 单一事实源。
本计划区分可在一次实现中验证的功能，与必须经过真实使用才能获得的证据。

| 工作项 | 本轮交付 | 验收方式 |
|---|---|---|
| GitHub 代码基线 | 私有仓库与可恢复提交 | 远端分支 SHA 与本地比对 |
| 提炼可靠性 | 八字段严格 JSON、永久发布恢复有界、显式恢复 | malformed/永久故障/版本并发夹具 |
| 召回隔离 | 默认排除测试材料，显式类型可读取 | 同名项目/旧版本/夹具负例 |
| 失败账本治理 | current/stale/legacy/missing/unreadable 等聚合分类 | 零写入与错误显式测试 |
| 知识质量 | model-extracted 标记、来源提示、去掉空维护模板、只读审计 | 合成产物与现有库聚合检查 |
| 召回效率 | 单次检索复用与请求内来源校验复用 | 原隔离回归和相同语料耗时 |
| 召回评测 | 中文与代码混合、调参/留出划分、安全负例 | benchmark 原始输出与失败样例 |
| 安装与交付 | wheel、CLI/MCP/Hook 入口、安全默认、CI | 干净检出与安装后独立目录运行 |
| 五端原生升级验收 | 保留历史回执，补统一适配器契约 | 仍需逐端新会话真实回执 |
| 真实任务收益 | 记录有用/无关/错误及来源 | 20 个真实任务，不能用合成题代替 |
| 连续稳定观察 | 每次有界只读检查 | 至少 7 天，不把当天实现称为完成观察 |

下一步按证据推进：
1. 把当前失败记录按输入版本、错误类别和可读性分层，不全量重试。
2. 使用无私人数据的单次提炼 canary 验证固定模型的当前路由和严格输出兼容性。
3. 选少量高价值旧来源，先输出映射/重提炼建议，再执行明确的数据范围；保留旧正文。
4. 新增真实中文任务标注，和现有关键词基线比较。只有出现可复现增益才引入 FTS、向量或外部检索组件。
5. 在五端原生新会话验收当前版本，记录来源、代码版本、事件、上下文摘要、游标和结果；不重启既有会话冒充验收。

当前不扩展独立 Web 控制台、公开远程服务、多租户或图数据库。知识数量增加不是验收条件。
